# SINOF Gear Domain Migration Design

## Objective

Migrate the production website from `https://sinfogear.com` to `https://sinofgear.com` without interrupting the website or inquiry delivery and without discarding the search value of existing URLs.

## Confirmed Decisions

- `https://sinofgear.com` is the only canonical production origin.
- `https://www.sinofgear.com` redirects permanently to `https://sinofgear.com`.
- Every URL on `sinfogear.com` redirects permanently to the same path and query on `sinofgear.com`.
- The domain remains registered and renewed through Xinnet.
- Authoritative DNS for `sinofgear.com` moves to Cloudflare by changing the nameservers at Xinnet.
- The existing Cloudflare Pages project `sinoform` continues to host the website.
- Inquiry delivery remains unchanged during this migration: messages continue to reach `452900431@qq.com`, and Resend continues sending from `inquiries@sinfogear.com`.
- Email migration is a later, independent phase after the enterprise mailbox is ready. That phase will verify `sinofgear.com` in Resend and change the sender to `inquiries@sinofgear.com`.

## DNS and Hosting Architecture

Xinnet remains the registrar, while Cloudflare becomes the DNS provider. Cloudflare will issue the two authoritative nameserver values that must replace the current nameservers in the Xinnet console.

The apex domain `sinofgear.com` and `www.sinofgear.com` will be added as custom domains for the current `sinoform` Pages project. The apex domain is the canonical address. The `www` hostname is only an alternate entry point and must return a 301 redirect to the apex domain.

The old domain stays active. Its homepage and every nested path redirect to the matching path on the new domain. For example:

```text
https://sinfogear.com/products/worm-gears
  -> 301 https://sinofgear.com/products/worm-gears
```

Redirect rules must preserve the path and query string. Redirects are not enabled until the new domain, TLS certificate, and production site have passed validation.

## Website and SEO Changes

The production site origin changes to `https://sinofgear.com` in runtime configuration, static generation defaults, tests, and deployment documentation. Generated output must use the new origin in:

- canonical links;
- XML sitemap locations;
- the sitemap reference in `robots.txt`;
- Open Graph URLs;
- organization, product, breadcrumb, FAQ, and article structured data;
- inquiry source URLs generated by the website;
- public deployment instructions.

Historical design and implementation documents remain historical records unless they are directly used as active deployment instructions. Active source code, tests, README instructions, and generated production output must not identify `sinfogear.com` as the canonical site.

## Email Boundary

Website-domain migration and enterprise-email migration are deliberately separated.

During this phase:

- `INQUIRY_TO_EMAIL` remains `452900431@qq.com`;
- `INQUIRY_FROM_EMAIL` remains `Sinoform RFQ <inquiries@sinfogear.com>`;
- the existing Resend API key and verified sending domain remain unchanged;
- no MX, SPF, DKIM, or DMARC records for the future enterprise mailbox are invented or changed.

When the enterprise mailbox is ready, a separate change will verify the new sending domain and update both the public RFQ address and Cloudflare environment variable.

## Migration Sequence

1. Add `sinofgear.com` to the existing Cloudflare account and obtain its assigned nameservers.
2. Replace the domain nameservers in Xinnet.
3. Wait for Cloudflare to confirm authoritative DNS activation.
4. Add `sinofgear.com` and `www.sinofgear.com` to the `sinoform` Pages project.
5. Confirm DNS validation and TLS issuance for both hostnames.
6. Update the website canonical origin and related tests.
7. Build, verify, and deploy the new production output.
8. Validate the new domain before enabling old-domain redirects.
9. Enable path-preserving 301 redirects from `www.sinofgear.com` and `sinfogear.com` to the apex new domain.
10. Add the new domain property to Google Search Console and submit `https://sinofgear.com/sitemap.xml`.

## Validation

The migration is complete only when all of the following are verified from the public internet:

- `https://sinofgear.com/` returns HTTP 200 with a valid TLS certificate;
- representative product, quality, contact, and article routes return HTTP 200;
- `https://www.sinofgear.com/` returns a permanent redirect to `https://sinofgear.com/`;
- representative old-domain URLs return permanent, path-preserving redirects;
- an unknown new-domain route returns the branded document with HTTP 404;
- page titles, canonical links, Open Graph URLs, and JSON-LD use `sinofgear.com`;
- `sitemap.xml` is valid XML and contains only `sinofgear.com` canonical URLs;
- `robots.txt` points to the new sitemap;
- the inquiry endpoint configuration and email secrets are unchanged;
- no real customer inquiry is submitted during automated verification without explicit approval.

## Failure Handling and Rollback

The old production domain remains live until the new domain passes DNS, TLS, page, and SEO checks. If nameserver propagation, certificate issuance, or Pages domain validation is incomplete, the redirect cutover is postponed and the current site continues serving traffic.

If a production problem is found after deployment, the latest known-good Cloudflare Pages deployment can be restored and the old-domain redirect can be disabled. Email delivery is isolated from this migration, so a website-domain rollback does not require changing Resend or mailbox records.

## Out of Scope

- Creating the enterprise mailbox.
- Moving the Resend sender to `sinofgear.com`.
- Changing the inquiry recipient address.
- Redesigning pages or changing product content.
- Changing the Cloudflare Pages project name.
